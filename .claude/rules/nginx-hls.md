# Nginx: раздача HLS и безопасность (источник: logic_of_operation.md 2.5, security.md)

## HLS
- Путь `/hls/<id видео>/<версия>/…` проксируется в бакет `hls` по внутренней сети Docker. Бакет наружу не опубликован.
- Проверка подписанной cookie (модуль `secure_link`) выполняется **до** обращения к кешу. Cookie с путём `/hls/<id>/`, срок жизни 30–120 минут с продлением. Секрет общий с backend, формат подписи совпадает до символа (кодирование base64!). Для MVP допустим `auth_request` с кешем ответа на минуту.
- Дисковый кеш: блокировка кеша (`proxy_cache_lock`), ключ без cookie, кешировать только успешные ответы (не 403 и 404), `Cache-Control` для версионных путей — неизменяемый и долгий.
- Типы содержимого: плейлисты `application/vnd.apple.mpegurl`, сегменты `video/mp2t`. Плейлисты сжимать можно, сегменты — нет. Скрыть служебные заголовки хранилища.
- Постоянные соединения с хранилищем, HTTP/2, эффективная отправка файлов.

## Поддомен загрузок
- Пропускает к хранилищу только PUT, POST, DELETE и OPTIONS (multipart-загрузка и CORS-запросы). GET и HEAD запрещены, чтобы нельзя было читать бакеты напрямую.
- Лимит размера тела увеличен только здесь. Строка запроса (в ней подписи presigned URL) в логи не пишется.

## Общая безопасность
- TLS 1.2 и 1.3, редирект на HTTPS, HSTS. `server_tokens off`.
- Заголовки: Content-Security-Policy (скрипты только со своего домена), защита от встраивания во фреймы, `X-Content-Type-Options`, `Referrer-Policy`.
- Лимиты тела по маршрутам (аватар — 5 МБ), таймауты чтения заголовков и тела, лимит соединений с IP, `limit_req` для `/api` и особенно `/api/v1/auth`.
- Реальный IP клиента берётся только из заголовка, который выставляет сам Nginx; клиентским заголовкам не доверять. Скрытые файлы запрещены.
- Статика фронтенда: файлы с хешем в имени — кеш на год, `index.html` — без кеша.

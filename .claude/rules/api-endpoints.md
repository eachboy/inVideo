# API-слой (источник: architecture.md 3.4–3.5)

- Список endpoint-ов, права и поля — в `architecture.md` 3.5. Новые endpoint-ы без согласования не придумывать; расхождение с документом сначала обсудить.
- Роутер тонкий: валидация через схему, зависимости, один вызов сервиса, возврат схемы. SQL и бизнес-правил в роутере нет.
- Префикс `/api/v1`. Коды: 201 создание, 202 принято в обработку, 204 без тела. Ошибки — только доменные исключения, формат единый.
- Схемы на вход и выход разные. Входные запрещают лишние поля (`extra="forbid"`), задают длины, диапазоны, шаблоны, enum. PATCH принимает только перечисленные поля (роль, счётчики и т. п. изменить нельзя).
- У каждого endpoint-а `response_model`. Хеш пароля, refresh-токены и внутренние числовые id наружу не попадают.
- Списки: общая схема `items` + `next_cursor`, `limit` до 50. Сортировки и фильтры — enum.
- Создание комментариев, плейлистов, загрузок принимает `Idempotency-Key`. Реакции, подписки, добавление в плейлист — PUT/DELETE и идемпотентны.
- Зависимости: `current_user` (обязательный), опциональный (гостевые endpoint-ы), требование роли admin. Rate limit — зависимость на чувствительных endpoint-ах.
- Гость и пользователь без прав на чужой приватный объект получают 404.
- В OpenAPI у каждого endpoint-а понятное описание: из схемы генерируются типы фронтенда.

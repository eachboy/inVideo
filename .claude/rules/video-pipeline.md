# Загрузка и обработка видео (источник: logic_of_operation.md 2.3–2.4, security.md)

## Загрузка
- Видео в API не передаётся. Инициализация создаёт запись `UPLOADING`, `video_uploads` и S3 multipart-загрузку. Ключ объекта генерирует сервер, имя файла пользователя в ключ не попадает.
- Часть 16 МиБ. Presigned URL на 1 час, в подпись входит MD5 части. URL подписывает отдельный S3-клиент с публичным адресом хранилища.
- Источник правды о загруженных частях — `ListParts`, а не браузер.
- Завершение: сверка частей и ETag, `CompleteMultipartUpload`, сверка итогового размера с заявленным, затем одна транзакция (`UPLOADED`, оригинал в `video_files`, задача, `QUEUED`) и отправка в Celery после коммита.
- Брошенные загрузки (старше 24 часов) прерываются задачей Beat; на бакете есть правило очистки незавершённых загрузок.

## Celery
- Очереди `video`, `default`, `notifications`. JSON, в задачу передаётся только id. `acks_late`, prefetch 1.
- `worker-video`: concurrency 1, перезапуск процесса после N задач, мягкий и жёсткий лимиты времени, visibility timeout брокера больше максимального времени обработки (например, 6 часов).
- Захват задачи — условное обновление QUEUED → PROCESSING; ноль строк — выйти молча. В `video_processing_jobs` не больше одной активной задачи на видео (частичный уникальный индекс).
- Сердцебиение задачи каждые 30 секунд. Подметальщик Beat раз в 5 минут возвращает зависшие PROCESSING в QUEUED (или переводит в FAILED) и повторно отправляет неотправленные QUEUED.
- Ошибки: временные (недоступны хранилище или БД, мало места, OOM) — повтор с задержкой 30 с, 2 мин, 10 мин, максимум 3 попытки; постоянные — сразу FAILED с кодом `UNSUPPORTED_FORMAT`, `NO_VIDEO_STREAM`, `DURATION_TOO_LONG`, `RESOLUTION_TOO_HIGH`, `CORRUPTED_FILE`. В задаче сохраняются код, сообщение и хвост stderr FFmpeg.

## FFprobe и FFmpeg
- Запуск списком аргументов, без shell. Белый список протоколов: только локальные файлы. Таймауты. Непривилегированный процесс с пониженным приоритетом.
- Читать stderr FFmpeg непрерывно (или писать в файл): переполненный буфер подвешивает процесс.
- Лесенка 360p/480p/720p/1080p, без апскейла; для вертикальных видео «качество» считается по короткой стороне.
- H.264 High + AAC стерео 48 кГц, `yuv420p`, поворот из метаданных применяется. Видео без аудиодорожки — нормальный случай.
- **Ключевые кадры через фиксированный интервал (2 с), без вставки на смене сцены** — иначе сегменты разных качеств не совпадут и переключение будет с рывками. Сегменты 6 секунд, MPEG-TS, тип плейлиста VOD.
- Master playlist загружается в хранилище **последним**. Финализация условна: READY только если видео всё ещё PROCESSING и задача — эта. Пути результатов содержат `processing_version`.
- Перед стартом проверить свободное место (нужно около трёх размеров оригинала). Временная директория удаляется в `finally`.
- Прогресс — в Redis раз в несколько секунд, не в БД.

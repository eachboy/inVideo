# Frontend (React + TypeScript SPA)

Спецификация: `docs/project/logic_of_operation.md` (экраны вытекают из процессов 2.1–2.12), `realization.md` (этап 11 и фронтенд-пункты каждого этапа), `architecture.md` 3.5 (API). Правила для плеера и загрузки — `.claude/rules/frontend-player-upload.md`.

## Команды (из каталога `frontend/`)

- `npm run dev` — dev-сервер (обычно через `make up` за Nginx)
- `npm run lint`, `npm run typecheck`, `npm run test`, `npm run build`
- `npm run gen:api` — генерация TypeScript-типов из OpenAPI backend (openapi-typescript)

## Структура `src/`

- `app/` — роутер и провайдеры; `api/` — HTTP-клиент и `schema.gen.ts` (не править руками).
- `features/<name>/` — auth, player, upload, videos, comments, channels, playlists, search, history, notifications, studio: компоненты, хуки запросов, логика области.
- `pages/` — страницы-маршруты, собирают фичи; `components/ui` и `components/layout` — общие компоненты; `stores/` — Zustand; `lib/` — утилиты; `styles/` — токены.

## Правила

- Типы запросов и ответов берутся только из сгенерированной схемы OpenAPI. Руками типы ответов API не описывать.
- Серверные данные живут только в TanStack Query, клиентское состояние (токен, текущий пользователь, настройки плеера) — в Zustand. Серверные данные в Zustand не копировать.
- Курсорная пагинация — через infinite queries. Реакции и подписки обновляются оптимистично с откатом при ошибке. После мутаций — явная инвалидация нужных ключей.
- Access-токен хранится только в памяти (не в localStorage). Обновление токена — один запрос на все вкладки (Web Locks API или BroadcastChannel); при `TOKEN_EXPIRED` клиент обновляет токен и повторяет исходный запрос.
- Пользовательский текст выводится только экранированным; HTML из пользовательских данных не вставлять. Ссылки в описаниях и комментариях — только http и https.
- Каждый экран обрабатывает три состояния: загрузка (скелетон), пусто, ошибка (с повтором). Ошибки API показываются по коду ошибки.
- Карточки видео имеют фиксированное соотношение сторон (без «прыжков» вёрстки). hls.js и Studio — отдельные чанки.
- Доступность: управление плеером с клавиатуры, видимый фокус, подписи кнопок, контраст.
- Дизайн: минимализм; акценты фиолетовый, оранжевый, зелёный через токены Tailwind; шрифт с кириллицей (Onest, Manrope или Inter). Тексты интерфейса — по-русски, строки собираются в одном месте для будущей локализации.
- Тесты: Vitest + React Testing Library, API мокается через MSW. Обязательно покрыть: диалог загрузки (пауза, ошибка части, продолжение), форму комментария (защита от повторной отправки), кнопку реакции (оптимистичное обновление и откат), HTTP-клиент (обновление токена и повтор запроса).

# Часть VI. MVP и расширение

MVP — это этапы 1–7 полностью плюс реакции, комментарии, учёт просмотров и поиск из этапов 8–9, минимальный кабинет автора и production-деплой с HTTPS и бэкапом базы. Это реально закончить одному разработчику, и это уже демонстрирует все сложные подсистемы: multipart-загрузку, фоновую обработку, HLS, авторизацию с ротацией токенов.

## Три уровня функциональности

К двум уровням из задания добавлен промежуточный — **MVP+**: функции, которые формально «дополнительные», но стоят дёшево и сильно улучшают впечатление от демо. Их стоит делать сразу после MVP, до всего остального.

## Что реализовать сразу и почему

- **Всё, что трудно добавить потом.** Статусы и их переходы, идемпотентность обработки, версия обработки в путях, разделение статуса и видимости, публичные идентификаторы вместо числовых, курсорная пагинация. Переделка любого из этих решений задевает половину проекта.
- **Всё, что формирует главную историю на собеседовании:** «загрузка гигабайтного файла напрямую в хранилище с докачкой → обработка в фоне с повторами → адаптивный HLS через кеширующий Nginx». Это ядро MVP.
- **Бэкап базы.** Production без бэкапа — не production; это полчаса работы.
- **Тесты и CI.** Без них нельзя безопасно улучшать проект после MVP.

## Что отложить и почему

- **Рекомендации** — эффектны, но без реальных пользователей их качество не проверить; тренды и свежее дают 80% впечатления за 10% работы.
- **Мониторинг** — важен для эксплуатации, но на демо-проекте с единицами пользователей логов хватает. Отличный первый шаг после MVP, когда появится время.
- **Telegram и уведомления** — независимые модули, легко добавляются поверх событий, которые уже есть.
- **Продвинутая статистика** — требует накопленных данных.

## Что заложить в схему заранее, даже если реализация позже

Поля, которые дёшево добавить сейчас и дорого — потом: is\_email\_verified, visibility, moderation\_status, category, comments\_enabled, processing\_version, notification\_settings. Таблицы для расширений (уведомления, плейлисты) не создаются заранее — их проще добавить миграцией, когда до них дойдёт очередь.

## MVP готов, когда

- [ ] Новый пользователь на публичном домене по HTTPS регистрируется, создаёт канал и загружает видео размером 1–2 ГБ.
- [ ] Обрыв сети во время загрузки не приводит к повторной загрузке с нуля.
- [ ] Видео обрабатывается в фоне, автор видит прогресс и понятную ошибку для битого файла.
- [ ] Видео проигрывается с переключением качества и быстрой перемоткой; приватное недоступно посторонним.
- [ ] Работают лайки, комментарии с ответами, поиск по названию с морфологией.
- [ ] Обновление страницы не накручивает просмотры.
- [ ] CI зелёный, есть README со схемой архитектуры и инструкцией запуска одной командой.
- [ ] Бэкап базы создаётся ежедневно за пределами сервера и хотя бы раз восстановлен.

# Часть I. Технологический стек

Предложенный стек принимается почти целиком. Изменения минимальные и обоснованные: менеджер пакетов **uv**, библиотека **PyJWT** вместо устаревшей python-jose, хеширование **Argon2id**, на фронтенде **TanStack Query** и **hls.js**, для тестов **testcontainers**. Ничего не добавлено «для количества»: каждая технология закрывает конкретную задачу.

В таблицах ниже столбец «Роль в inVideo» отвечает сразу на вопросы «для чего используется» и «какую задачу решает».

## 1. Backend

| Технология | Роль в inVideo | Почему выбрана | Альтернативы и сравнение |
| --- | --- | --- | --- |
| **Python 3.12+** | Язык всего backend и воркеров | Целевой язык вакансии; 3.12 быстрее 3.11, лучше сообщения об ошибках, новый синтаксис дженериков | Go быстрее, но цель проекта — показать Python. Python 3.13 допустим, но часть библиотек может отставать |
| **FastAPI** | HTTP API: роутинг, валидация, OpenAPI-документация, DI | Асинхронный, автогенерация Swagger, встроенный Depends для внедрения зависимостей, стандарт рынка для новых проектов | Django + DRF: больше «батареек» (админка, ORM), но тяжелее и менее показателен для async. Litestar: сильный, но менее востребован в вакансиях |
| **Uvicorn** (через Gunicorn или с `--workers`) | ASGI-сервер, запускающий FastAPI | Стандартная пара для FastAPI в продакшене | Hypercorn, Granian — работают, но меньше документации и опыта у сообщества |
| **SQLAlchemy 2.0** (async в API, sync в воркерах) | ORM и построитель запросов к PostgreSQL | Типизированные модели (`Mapped`), явный контроль запросов, поддержка async через asyncpg | SQLModel проще, но скрывает SQLAlchemy и ограничивает в сложных запросах. Tortoise ORM — меньше экосистема. Сырой asyncpg — много ручной работы |
| **asyncpg** / **psycopg 3** | Драйверы БД: asyncpg для API, psycopg для синхронных Celery-задач | asyncpg — самый быстрый async-драйвер; Celery-задачи синхронные, им проще sync-сессия | Можно использовать один psycopg 3 в обоих режимах — это тоже корректный выбор, если хочется одной зависимости |
| **Pydantic v2** + **pydantic-settings** | Схемы запросов и ответов, валидация, конфигурация из переменных окружения | Ядро на Rust, быстрый; встроен в FastAPI | marshmallow, attrs — устаревший подход для FastAPI |
| **Alembic** | Версионированные миграции схемы БД | Официальный инструмент для SQLAlchemy, автогенерация черновиков миграций | Ручные SQL-скрипты — нет истории и отката. Yoyo, Flyway — не интегрированы с моделями |
| **PyJWT** | Выпуск и проверка JWT access-токенов | Активно поддерживается, минимальный | python-jose практически не поддерживается и имел уязвимости — не брать. Authlib мощнее, но избыточен |
| **argon2-cffi** (или **pwdlib**) | Хеширование паролей алгоритмом Argon2id | Победитель Password Hashing Competition, рекомендован OWASP | bcrypt — приемлем, но ограничен 72 байтами пароля. passlib не развивается |
| **boto3** | Работа с MinIO по S3 API: presigned URL, multipart upload, загрузка результатов | S3 API универсален: код без изменений работает с AWS S3, Yandex Object Storage, Selectel | miniopy — привязан к MinIO. aioboto3 — асинхронный, но нестабилен; presigned URL генерируются локально без сети, поэтому синхронный boto3 в API не блокирует |

## 2. Frontend

| Технология | Роль в inVideo | Почему выбрана | Альтернативы и сравнение |
| --- | --- | --- | --- |
| **React 18/19** | UI всей платформы | Самый распространённый фреймворк, огромная экосистема | Vue проще, Svelte легче, но React даёт больше пользы для резюме |
| **TypeScript** | Типизация фронтенда | Ловит ошибки контрактов с API до запуска | JavaScript — без проверки типов, ошибки обнаруживаются в рантайме |
| **Vite** | Сборка и dev-сервер | Мгновенный старт, простая конфигурация | Next.js даёт SSR, но здесь SPA достаточно, а SSR добавляет отдельный Node-сервер в инфраструктуру. Create React App устарел |
| **Tailwind CSS** | Стили и дизайн-система | Быстрая разработка, токены цветов и шрифтов в одном месте | CSS Modules, styled-components — медленнее итерации |
| **React Router** | Маршрутизация страниц | Стандарт для SPA | TanStack Router — хорошая типизация, но меньше материалов |
| **TanStack Query** | Загрузка и кеширование данных с API, пагинация, инвалидация | Убирает 80% ручного кода состояния: кеш, повторы, бесконечная лента | Redux Toolkit Query — тяжелее; ручной useEffect — много ошибок |
| **Zustand** | Небольшое клиентское состояние: access-токен, текущий пользователь, настройки плеера | Минимальный, без шаблонного кода | Redux — избыточен для такого объёма; Context — лишние перерисовки |
| **hls.js** | Воспроизведение HLS в Chrome/Firefox (Safari умеет нативно) | Де-факто стандарт, адаптивный битрейт из коробки | Video.js (обёртка над тем же движком, тяжелее), Shaka Player (сильнее в DASH/DRM, не нужен) |
| **Uppy** (модуль AWS S3 Multipart) | Загрузка больших файлов частями с докачкой | Работает с вашими endpoint-ами инициализации и подписи частей; прогресс, пауза, повтор | Собственный загрузчик — хороший учебный опыт, но 1–2 недели работы. tus-js-client требует отдельный tus-сервер |
| **react-hook-form** + **zod** | Формы и их валидация | Мало перерисовок, схемы валидации переиспользуются | Formik — медленнее и менее активен |

Визуальное направление: минималистичный интерфейс, акцентные цвета фиолетовый, оранжевый и зелёный задаются токенами в конфигурации Tailwind. Шрифт с полной кириллицей — например, Onest, Manrope или Inter.

## 4. Cache и очереди задач

| Технология | Роль в inVideo | Почему выбрана | Альтернативы и сравнение |
| --- | --- | --- | --- |
| **Redis 7** | Брокер Celery, кеш, rate limiting, дедупликация просмотров, счётчики, блокировки | Одна технология закрывает пять задач | Valkey — совместимый форк, можно взять вместо Redis без изменений. Memcached — только кеш |
| **Celery 5** | Фоновые задачи: обработка видео, уведомления, пересчёт счётчиков, периодические задачи (Celery Beat) | Зрелый, отдельные очереди, retry, time limits, мониторинг, массово встречается в вакансиях | Dramatiq — проще и надёжнее по умолчанию; ARQ/Taskiq — нативно async. Celery выбран ради востребованности и зрелого инструментария |

RabbitMQ как брокер надёжнее Redis при потере соединений, но это лишний сервис. Для одного разработчика Redis-брокера достаточно при правильных настройках (см. раздел 2.4).

## 7. Object Storage

| Технология | Роль в inVideo | Почему выбрана | Альтернативы и сравнение |
| --- | --- | --- | --- |
| **MinIO** | Хранение оригиналов, HLS-сегментов, превью, аватаров | S3-совместимый, self-hosted, бесплатный, поддерживает presigned URL и multipart | Локальная файловая система — не масштабируется и нет multipart API. Облачный S3 — платно, но код тот же, переезд — смена переменных окружения |

**Важное предупреждение о MinIO.** Community-версия MinIO фактически прекратила развитие: в мае 2025 урезана веб-консоль, осенью 2025 перестали публиковаться официальные Docker-образы и бинарники, в декабре 2025 объявлен режим поддержки, а в 2026 году репозиторий заархивирован ([хронология](https://www.youngju.dev/blog/2026-07-17-minio-archived-garage-seaweedfs-ceph-rgw.en), [обзор альтернатив](https://glukhov.org/data-infrastructure/object-storage/minio-dead/)). Последствия для inVideo:

- Весь код работает только через S3 API (boto3) и не использует ничего MinIO-специфичного. Тогда хранилище меняется заменой переменных окружения.
- Для разработки и демонстрации MinIO по-прежнему подходит: используйте поддерживаемую сообществом сборку (например, образ `pgsty/minio` из [проекта Pigsty](https://blog.vonng.com/en/db/minio-resurrect/index.md)) с зафиксированной версией. Официальный образ `minio/minio` не обновляется и не получает исправлений безопасности.
- Резервный вариант — **Garage** или **SeaweedFS**: оба S3-совместимы и активно развиваются. Перед переходом проверьте, что выбранное хранилище поддерживает нужное: presigned URL, multipart upload, CORS на бакете и правило автоматической отмены незавершённых multipart-загрузок.
- Управление бакетами делайте через S3 API или скрипт инициализации, а не через веб-консоль.

## 8. Infrastructure

| Технология | Роль в inVideo | Почему выбрана | Альтернативы и сравнение |
| --- | --- | --- | --- |
| **Docker** | Упаковка каждого сервиса в образ | Одинаковое окружение в разработке и продакшене | Запуск на хосте — «работает только у меня» |
| **Docker Compose** | Оркестрация всех сервисов на одном сервере | Достаточно для одного VPS, просто | Kubernetes — избыточен для одного узла и одного разработчика; Docker Swarm — малораспространён |
| **Nginx** | Reverse proxy, HTTPS, раздача фронтенда, раздача HLS с кешем, проверка доступа к приватным видео, rate limiting | Самый быстрый для статики, модули secure\_link и auth\_request | Caddy — автоматический HTTPS, проще конфиг, но меньше примеров для HLS. Traefik — удобен с Docker, но слабее как кеширующий файловый сервер |
| **Let's Encrypt** (certbot) | Бесплатные TLS-сертификаты | Стандарт | Платные сертификаты не нужны |
| **Linux VPS** (Ubuntu 24.04 LTS / Debian 12) | Продакшен-сервер | Полный контроль, недорого | PaaS (Render, Railway) — дороже на тяжёлых CPU-задачах и не показывает DevOps-навыки |

Требования к VPS: транскодирование нагружает процессор. Минимум 4 vCPU и 8 ГБ RAM; диск — от 100 ГБ, потому что час видео в лесенке до 1080p вместе с оригиналом занимает порядка 2–4 ГБ.

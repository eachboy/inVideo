# Часть X. Финальный результат

inVideo — модульный монолит на FastAPI с отдельными Celery-воркерами: видео загружается из браузера напрямую в S3-хранилище частями, обрабатывается FFmpeg в фоне в HLS-лесенку 360p–1080p и раздаётся Nginx с кешем и подписанным доступом. MVP — 280–400 часов, полная версия — 420–620 часов. Ниже — сводка всех частей и то, чего нет в остальных вкладках: Definition of Done и список самых сложных задач.

## Definition of Done

### Для каждой функции (задачи, pull request)

- [ ] Код типизирован, проходит Ruff и mypy в строгом режиме.
- [ ] Входные и выходные данные описаны Pydantic-схемами; endpoint-ы видны в OpenAPI с понятными описаниями.
- [ ] Права доступа проверены в сервисе; чужие приватные объекты возвращают 404.
- [ ] Тесты покрывают основной сценарий, ошибки, права доступа и повторный запрос.
- [ ] Миграция прочитана, имеет откат и обратно совместима.
- [ ] Новые запросы проверены через EXPLAIN; нужные индексы созданы; нет N+1.
- [ ] Ошибки возвращаются в едином формате с кодом; логи содержат контекст и не содержат секретов.
- [ ] Экран фронтенда подключён к endpoint-у и обрабатывает загрузку, пустое состояние и ошибку.
- [ ] Пройден чек-лист ревью из Части VIII.
- [ ] CI зелёный; изменение задеплоено и проверено smoke-тестом (после этапа 7).
- [ ] README, ADR, .env.example обновлены, если затронуты.

### Для всего проекта

- [ ] Все критерии «MVP готов» из Части VI выполнены, затем все критерии завершения этапов 8–13.
- [ ] Приложение работает на публичном домене по HTTPS; push в main деплоится автоматически и откатывается при неудаче.
- [ ] Пайплайн обработки проходит матрицу тестовых видео; сбой воркера и двойная доставка задачи не ломают результат.
- [ ] Приватные видео недоступны посторонним ни через страницу, ни через прямые ссылки на сегменты, ни через поиск и ленты.
- [ ] Покрытие backend не ниже 80%, e2e-сценарии зелёные, CI быстрее 15 минут.
- [ ] Дашборды показывают API, очереди, пайплайн, базу и диск; тестовый алерт доходит в Telegram.
- [ ] Бэкап хранится вне сервера, восстановление проверено и описано в runbook.
- [ ] README с демо, схемой и ключевыми решениями; 6–10 ADR; вы можете за 2–3 минуты объяснить каждую тему из списка в Части VIII.

## Самые сложные технические задачи

В порядке убывания сложности. Именно эти задачи стоит рассказывать на собеседовании — они показывают уровень выше «CRUD на FastAPI».

| № | Задача | Почему сложно | Как не утонуть |
| --- | --- | --- | --- |
| 1 | Надёжный пайплайн обработки | Повторы, падения воркера, повторная доставка по visibility timeout, зависшие задачи, удаление видео посреди обработки — всё должно сходиться к корректному состоянию | Условный захват, детерминированные пути, условная финализация, подметальщики; тесты на каждый сценарий сбоя |
| 2 | Корректное транскодирование в HLS | Выравнивание ключевых кадров между качествами, поворот, видео без звука, нестандартные пропорции и частота кадров, без апскейла | Вертикальный срез с одним качеством; матрица синтетических тестовых видео; проверка в нескольких браузерах |
| 3 | Multipart-загрузка с докачкой | Presigned URL на публичном хосте, CORS и ETag, восстановление по ListParts, проверка целостности, очистка брошенных загрузок | Тест, играющий роль браузера; проверка на реальном домене сразу после этапа 7 |
| 4 | Доступ к видео без Python в раздаче | Подписанные cookie, совпадение формата подписи у backend и Nginx, порядок «проверка до кеша», смена видимости | Сначала auth\_request, затем secure\_link; smoke-тесты Nginx в CI |
| 5 | Ротация refresh-токенов | Обнаружение повторного использования, гонки между вкладками, мгновенный отзыв короткоживущего JWT | Окно гонки, блокировка обновления между вкладками, Redis-список отозванных сессий |
| 6 | Учёт просмотров | Защита от накрутки без капчи, дедупликация, пакетная запись без потери данных | Токен просмотра с проверкой возраста, атомарные операции Redis, тест сброса дельт |
| 7 | Консистентность счётчиков и порядка | Конкурентные реакции и подписки, позиции в плейлистах | Атомарные выражения в UPDATE, блокировка строки родителя, конкурентные тесты, ночная сверка |
| 8 | Поиск на русском и английском | Морфология, опечатки, ранжирование, производительность на больших объёмах | Конфигурация russian, триграммы как резерв, частичные индексы, 100 тысяч тестовых записей |
| 9 | Рекомендации | Нормирование признаков, стабильная пагинация, холодный старт | Чистая функция оценки с unit-тестами, кеш готового списка, тренды для новых пользователей |
| 10 | Эксплуатация на одном VPS | CPU-тяжёлая обработка рядом с базой, диск, бэкапы, деплой с миграциями без простоя | Лимиты контейнеров, алерты на диск и очередь, бэкап только базы и оригиналов, миграции отдельным шагом |

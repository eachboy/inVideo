# Infrastructure (Docker Compose, Nginx, мониторинг)

Спецификация: `docs/project/realization.md` (этапы 1, 7, 13), `security.md` (Nginx, MinIO, секреты, FFmpeg-изоляция), `architecture.md` 3.1. Правила для конфигов Nginx — `.claude/rules/nginx-hls.md`.

## Структура

- `docker-compose.yml` — разработка: все сервисы, код с автоперезагрузкой, порты наружу только для отладки.
- `docker-compose.prod.yml` — продакшен: образы из GHCR по тегу-хешу коммита, без лишних портов, лимиты CPU и памяти, политики перезапуска, healthchecks.
- `nginx/`, `postgres/init/`, `storage/init-buckets.sh`, `monitoring/{prometheus,grafana}`, `scripts/{deploy,backup,restore}.sh`.

## Правила Compose

- Версии образов зафиксированы, `latest` не использовать.
- У каждого сервиса healthcheck; `depends_on` только с `condition: service_healthy` для БД, Redis и хранилища.
- Данные — в именованных томах. Порты PostgreSQL, Redis, хранилища, Prometheus и Grafana наружу не публикуются (в dev допустимо только на `127.0.0.1`).
- Сети разделены: наружу смотрит только Nginx; БД и Redis — только во внутренней сети. `worker-video` без выхода в интернет.
- Контейнеры работают от непривилегированного пользователя; где возможно — read-only файловая система и `cap_drop: ALL`; `worker-video` пишет только в выделенный том для временных файлов.
- Лимиты в проде: у `worker-video` не больше ядер и памяти, чем нужно, чтобы одно ядро и 1–2 ГБ оставались API, БД и Nginx.
- Миграции выполняются отдельным контейнером до обновления сервисов, а не при старте каждого контейнера API.
- Секреты — только в `.env` на сервере (права только для владельца) и в секретах GitHub Actions. В образах, аргументах сборки и логах секретов нет.

## Хранилище

- Скрипт `init-buckets.sh` создаёт бакеты (`originals`, `hls`, `images`), политики, CORS для загрузки (origin фронтенда, нужные методы, открытый заголовок `ETag`) и правило удаления незавершённых multipart-загрузок.
- Root-ключи нужны только этому скрипту. У API и воркеров отдельные ключи с минимальными правами.
- Локально используется поддерживаемая сборка MinIO с зафиксированной версией. Всё, что завязано на конкретный движок, остаётся в этом каталоге, а не в коде приложения.

## Эксплуатация

- Деплой: pull образов по хешу → миграции → обновление сервисов → проверка здоровья → автоматический откат при неудаче. Миграции обратно совместимы.
- Бэкапы: ежедневный зашифрованный дамп PostgreSQL и копии оригиналов — за пределами сервера. HLS и обложки не бэкапятся (восстанавливаются повторной обработкой). Восстановление регулярно проверяется.
- Алерты: диск больше 80%, доля 5xx больше 2%, очередь `video` растёт дольше 30 минут, воркер недоступен, сертификат истекает через 14 дней, бэкап старше 26 часов.
- Сервер: вход по SSH-ключу, firewall (22, 80, 443), fail2ban, автообновления безопасности, Docker API не открыт в сеть.
